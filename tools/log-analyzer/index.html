Common Questions

Frequently Asked Questions

Find answers about log privacy, supported file types, threat scoring, brute-force detection, IOC extraction and the limitations of automated security analysis.

Are uploaded log files sent to ThreatHawk?

No. Log Analysis processes supported files directly in your browser. ThreatHawk does not intentionally upload, store or maintain a personal history of the log files you analyze. Even so, avoid using confidential production logs on shared or untrusted devices because the browser and local system still handle the data.

Which log file types are supported?

The current Log Analysis module accepts TXT, LOG and CSV files. The parser is designed for common authentication and security-event formats, but highly customized or unusual log structures may not be interpreted perfectly without additional formatting support.

How is the threat score calculated?

The threat score is based on detected security signals such as repeated failed logins, suspicious IP addresses, alert patterns, IOC matches and other notable events. These indicators are combined into an overall severity score so investigators can quickly understand the apparent level of risk.

How does ThreatHawk detect brute-force activity?

ThreatHawk looks for repeated authentication failures and groups suspicious patterns by source, event type and occurrence frequency. A large number of failed attempts from the same source may indicate password guessing or automated brute-force activity.

What are indicators of compromise?

Indicators of compromise, commonly called IOCs, are values that may be associated with suspicious or malicious activity. In the current module, these primarily include IP addresses extracted from the submitted log and counted across repeated events.

Can Log Analysis confirm that an incident occurred?

No. The module identifies suspicious patterns and produces an explainable assessment, but it cannot independently prove that a security incident occurred. Results should be reviewed alongside system context, endpoint evidence, network data and other investigative sources.

Why might legitimate activity be flagged as suspicious?

Legitimate systems can generate repeated failures, unusual IP activity or noisy alerts during testing, configuration changes, user mistakes or automated processes. The analyzer reports suspicious characteristics, not final guilt verdicts, despite software occasionally behaving as if it has joined a courtroom drama.

Can I search and filter the analyzed events?

Yes. After analysis, you can search parsed events by message, IP address or event details and filter the table by severity. This helps narrow large datasets to the events most relevant to an investigation.

Can I export the incident analysis?

Yes. The Export Analysis Report feature generates a report from the current incident summary, threat score, findings, indicators and parsed events for documentation or further investigation.

Is Log Analysis a replacement for a SIEM?

No. ThreatHawk Log Analysis is a lightweight browser-based investigation tool. It does not replace a full SIEM, continuous monitoring platform, endpoint detection system or professional incident-response workflow.
